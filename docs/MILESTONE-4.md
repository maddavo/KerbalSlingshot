Build: **0.3.0**, assembly **0.3.0.0**, Release `net48`, KSP **1.12.5**. This implements the corrected product contract at `74ba2f2`. Exact commit and SHA-256 are recorded in the clean-build/package manifest. It is a test build awaiting a meaningful live KSP session, not a claimed in-game pass.

## Implemented

- Normal pilot controls are Mun/Minmus selections, destination periapsis km, **Find Trajectory**, review, and **Create Node**. No import, manual burn, or preliminary node is required or exposed in the normal UI.
- From the immutable live snapshot, generate departure epochs, short/long zero-revolution Lambert transfers, safe flyby impact offsets and twelve azimuths. Approximate outgoing conics rank internal guesses; finite-SOI propagation and bounded local refinement determine feasibility. No seed is presented as an accepted trajectory.
- Initial live route is restricted to a stock Kerbin parent with Mun assist and Minmus destination, outside child SOIs. Existing future nodes do not prevent detached search, but prevent trustworthy validation/insertion. Other routes remain unsupported.
- Default departure interval is snapshot UT +600 through +87000 seconds (one-day window after a ten-minute lead), journey limit 1,200,000 s, departure DV limit 2,000 m/s, 6,000 evaluations and 120 s wall budget. Defaults include 10 km conservative stock terrain ceiling, 1 km margin, 20 km minimum Mun altitude, 30 km requested Minmus altitude, and 100 m altitude tolerance. Changed ceiling values require acknowledgement; defaults do not require configuring a burn or algorithm.
- Safeguarded Newton within the existing universal-variable bracket improves propagation cost. Existing independent RK4/analytic checks still pass. An unsafe destination retains a useful periapsis-error score for exploration, but is always rejected. Automatic refinement targets one quarter of the requested altitude tolerance to leave room for KSP agreement.
- Installed KSP APIs were inspected locally. Native node construction uses fixed orbital `Orbit.State` vectors, `QuaternionD.LookRotation`, `.xzy` ordering and then the current Z-up transform. `GetBurnVector` is the predicted-patch velocity difference in swapped raw order. The previous check mixed these representations. The adapter now follows the native fixed-vector construction and independently checks quaternion axes and a disposable node/patch velocity round trip.
- Before enabling creation, main-thread validation uses only temporary Orbit/ManeuverNode objects (not live solver nodes), checks KSP's preburn coast, full Kerbin/Mun/Kerbin/Minmus chain, SOI states, periapsis inside each encounter interval, parent/child clearance, unbound Mun exit/energy continuity, event times (5 s maximum numerical/KSP difference), destination altitude tolerance, future-node conflicts and freshness.
- **Create Node** repeats validation and freshness, adds one native departure node, updates its plan, checks node-list integrity and actual UT/vector, then checks its real resulting KSP patches. A failure removes only the node introduced by that operation. No existing node is silently replaced/deleted; no burn/warp/save action is performed beyond KSP's ordinary recording of the explicitly created node.
- Status distinguishes numerical candidate, KSP agreement/disagreement, stale/conflicted/incomplete validation, bounded failure and insertion success/failure. Diagnostics contain search bounds, numerical and KSP event evidence and native components.
