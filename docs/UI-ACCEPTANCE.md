# Compact planner visual acceptance — next single KSP session

Target: KSP 1.12.5, 1920×1080, normal UI scale initially; use a recoverable copy of the same supported shared-parent flight and estimate as the first session. Record game/UI scale, build manifest and installed DLL hashes. This checklist is prepared before the UI implementation. No new loading or trajectory-validation result is asserted.

1. Open Slingshot through its **stock KSP toolbar icon**. No floating Slingshot button should remain. Targets, adjacent **km** unit, recommended **Import existing node**, distinct Evaluate/Refine actions, status, and the five-event result card should be visible without scrolling. The initial window should be narrower/shorter than 0.2.0, away from the navball, staging strip, altimeter, and right resource strip where practical. Drag it; toggle it closed/open with the toolbar. Check hiding releases ship controls and the toolbar is not duplicated across flight/map/scene transitions in the same session.
2. Import the existing future node without altering it. The estimate summary should show departure UT and delta-v. Expand **Manual estimate**; UT and the three native components should be grouped, with seconds/m/s explained once. Collapse it again.
3. Open **Advanced — safety review required**. Verify all existing safety/search values are present, editable and unchanged by expand/collapse. Check terrain assumptions and acknowledgement. Invalid text/unsafe inputs must still prevent calculation or produce explicit validation errors. Collapse Advanced; readiness should now be clear.
4. Evaluate the estimate, then refine it. During calculation, inputs/import/refresh/competing actions should be disabled. **Cancel** and progress must remain visible. Cancel one calculation, then repeat to completion. Confirm cancellation and stale-state safeguards still apply.
5. Inspect a full prediction if available and a deliberately constrained miss. Status should be prominent and use readable contrast/text. Results should show departure UT, delta-v, assist entry/periapsis/exit, destination entry/periapsis, and altitude error/tolerance. Missing events must appear as missing, not zero or success. **Unvalidated — compare with KSP** must remain explicit; a miss must say no solution found within bounds.
6. Expand optional Details for the existing read-only KSP patch summary and full numeric evidence; save diagnostics if needed. The pilot workflow must not become a giant scrolling form. Only expanded secondary panels should scroll when their content exceeds available space.
7. Compare vessel node count/UT/components and save state before/after plugin actions. No node edits, burn execution, time warp, or save mutation may occur. Manual comparison edits from the older trajectory procedure are not required for this UI check.

Capture screenshots of idle/ready, Advanced expanded/collapsed, manual estimate, running/cancelled, complete or partial result, and constrained miss. Include clipping/overlap/focus issues, resolution/UI scale, build manifest, diagnostics, and relevant KSP.log exceptions. Actual font metrics, scaling, contrast in flight, and interaction are pending this session; offline layout checks are not rendered in-game evidence.
